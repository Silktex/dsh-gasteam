## DSH packaging

Dark Factory extends the existing coordinator plugin. Its host API is exposed as `dsh-team/darkfactory` in the single-package distribution and `@deepseek-ai/dsh-experimental-agent-team/darkfactory` in the development packages. Importing it starts no service. The default DSH bundle continues to load the existing Team services. The distributed subpath includes its TypeScript declaration closure; an isolated installed-package consumer checks all 20 public record types with both NodeNext and Bundler module resolution.

Contract schemas describe records, not permission to execute them. `contractJsonSchemas()` generates the lifecycle record schemas; `authorityJsonSchemas()` generates the policy/control schemas. `validateContract()` additionally checks local semantic constraints. Signature verification, referenced artifact lookup and current effect authority require runtime controllers. Raw schema errors are internal diagnostics and must be sanitized before logging untrusted inputs or returning ingress responses.

[Project-scoped contract codecs](../packages/agent-team/src/darkfactory/contract-codecs.ts) use the existing strict Typert codec format. [Gateway tests](../packages/agent-team/tests/darkfactory/contract-codecs.spec.ts) round-trip all 20 public records through the published DSH gateway and strict result decoding, reject cross-project and credential-field extensions before invocation, and keep rejected values out of diagnostics. Creating a codec registers no endpoint. Narrative must still be sanitized by its source owner; codecs cannot identify arbitrary secrets in valid prose.

The coordinator accepts `darkFactory: { enabled: false }` and defaults to disabled when omitted. Enabled `observe` mode now starts authenticated HTTP custody for already registered projects, after host preflight. It resolves ingress secrets, starts a loopback listener and records exceptions in the existing project health inbox. Configured GitHub issue/PR/Dependabot routes can also run bounded read-only reconciliation against the registered provider API. It does not discover models, contact Redis, call paid providers, create Dark Factory tasks, publish or deploy. `build`, `staging` and `production` startup remain rejected with `RUNTIME_UNIMPLEMENTED`; maintenance scanning is also unimplemented. See [observe configuration and operation](darkfactory-observe.md) and [the complete example policy](../examples/darkfactory-observe.json).

[Authentication](../packages/agent-team/src/darkfactory/ingress-auth.ts) verifies original body bytes for GitHub and Sentry, and binds method, registered path, key ID, delivery ID, timestamp and body digest for generic APM. Only the generic timestamp establishes the five-minute freshness window. Native header timestamps remain unauthenticated metadata. [Adapters](../packages/agent-team/src/darkfactory/ingress-adapters.ts) normalize GitHub issues, pull requests and Dependabot alerts, Sentry issue/event/metric alerts, and generic APM observations. Provider URLs never choose project authority or fetch destinations. Native extensions are discarded; the owned generic schema rejects unknown fields.

[Source scope checks](../packages/agent-team/src/darkfactory/ingress-scope.ts) compare configured installations, repositories, actors/authors, provider projects, environments and automation-rule mappings. Sentry project IDs/slugs remain distinct from Git repository IDs; event-alert rule labels require an explicit mapping. Eligible observations stay unresolved until provider reconciliation. Missing native environment evidence is never defaulted to production.

[The ingress owner](../packages/agent-team/src/darkfactory/ingestion-store.ts) persists custody before `202`, deduplicates both delivery identity and body digest, and returns `200` with the original receipt on redelivery. Conflicting delivery bodies and authenticated malformed/out-of-scope observations require durable quarantine references. Webhook custody persists sanitized lookup facts and content digests; raw request bodies, webhook narratives and stack payloads are withheld. Optional GitHub issue/PR/Dependabot enrichment separately retains bounded, redacted provider narrative and provenance. Factory incidents share the existing health inbox and its Lead authorization/acknowledgement flow. Acknowledgement does not resolve the incident, establish trust or admit work; disabling the listener preserves that history.

[GitHub issue reconciliation](../packages/agent-team/src/darkfactory/github-reconciliation.ts) and [PR reconciliation](../packages/agent-team/src/darkfactory/github-pr-reconciliation.ts) share a bounded transport and use a host-pinned installation-token reference, installation/repository IDs and repository name. The [driver](../packages/agent-team/src/darkfactory/reconciliation.ts) verifies the registered Git repository's actual GitHub origin, re-resolves the credential per attempt, verifies token repository visibility and fetches the current issue or PR through host-controlled paths. PR reads pin base/head repository IDs and full SHAs, reject initial/current forks and missing head repositories, and deny closed or merged PRs. Changed current commits produce a new source revision. Current author, actor allowlist, open state and configured automation label are required. The host rechecks authority before committing trust. Source revisions hash original execution-relevant fields; persisted provider narrative uses a bounded credential-pattern redactor, which does not classify arbitrary confidential prose. See the [optional route configuration](darkfactory-observe.md#optional-github-issue-and-pull-request-reconciliation). These requests are read-only host operations and do not call paid models.

[Dependabot reconciliation](../packages/agent-team/src/darkfactory/github-dependabot-reconciliation.ts) now fetches the current alert through the same registered transport. It requires an explicit host sensor principal and one permitted automation-rule mapping, verifies open alert/advisory/package/manifest facts, and hashes original execution-relevant fields before redaction. The API does not supply a current human initiator: work identifies the configured host sensor, while provenance keeps the signed webhook actor separate. Missing patched versions remain absent and do not imply a compatible fix or runnable reproduction.

[The shared request owner](../packages/agent-team/src/darkfactory/provider-request-store.ts) syncs each actual GET before transport and enforces 55 requests per rolling minute across the coordinator. It preserves uncertain charges, configured route changes and reduced limits on replay, and persists provider cooldowns before further requests. Project order rotates from the last persisted request charge, including after restart, so backlogged projects take turns. Recent cursor history conservatively withholds the remainder of its minute on startup to cover legacy readers. Standalone SDK hosts without the shared owner retain the legacy five-start bound. Response bodies are bounded at 1 MiB, requests at five seconds and the provider-read phase at fifteen seconds; close aborts provider work. Three attempts and durable retry leases survive restart. Conflicting attachments, changed active sources, source denial and exhausted attempts require inbox evidence. The optional [GitHub issue/PR scanner](darkfactory-scanning.md) shares this owner. Sentry/APM trust, other provider polling and live provider conformance remain open.

[The offline reference-graph validator](../packages/agent-team/src/darkfactory/contracts/reference-graph.ts) closes a bounded source/admission lane across envelope, work, custody, spec, compiler and admission records, registered definitions and artifact bytes. It validates references and immutable digests; it does not establish live provider, execution or economic authority. The source-only API keeps its original lane boundary. [The factory dispatcher](../packages/agent-team/src/darkfactory/contracts/factory-reference-graph.ts) additionally selects bounded verification/release, fleet/economics and quarantine/health validators, and `factoryReferenceGraphJsonSchemas()` generates their input schemas. The verification lane binds evidence, critics, mutant manifests, integrations, deployment identities and telemetry to registered definitions. The economics lane binds assignments, catalogs, pricing, reservations, requests, quota snapshots and usage streams. The quarantine lane binds concrete terminal records and operational events to real factory inbox incidents. Each validator checks its own declared relationships; [combined snapshots](../packages/agent-team/src/darkfactory/contracts/reference-snapshot.ts) now compare shared payloads and typed references across explicitly declared lanes, including a coherent four-lane fixture. Progressed source records carry complete native work histories from received revision 1 through the current payload; compiler context binds the exact trusted historical version. Quarantined records require concrete matching incidents and operational events, including the admission/work pair that shares one native incident. Source-health events with a release reference remain explicitly unsupported, and source attempt references require an explicit matching workflow; current native ingestion/admission producers do not emit those unsupported contexts. Live authority/signature/execution validation remains separate.

[Compiler host validation](../packages/agent-team/src/darkfactory/spec-compiler.ts) accepts bounded proposals referencing registered checks, commands, fixtures, assertions and paths. It validates source-bound reproduction evidence and purpose grants, pins the resulting spec, and allows one malformed-output repair before quarantine. [Durable compiler orchestration](darkfactory-compilation.md) now persists the full context, attempt identity, native outcome/cursor and exact admission handoff. Explicit recovery distinguishes saved results, proven unstarted requests and uncertainty; the latter quarantines. Observe does not invoke a compiler or model. Live provider calls and coordinator configuration remain open. Synthetic contract signatures are placeholders, not accepted runtime evidence.

[The admission store](../packages/agent-team/src/darkfactory/admission-store.ts) persists the full compiler outcome/cursor, immutable spec, registered Lead, workflow template/parameters and policy references before materialization. It derives deterministic admission/workflow/task identities, checks replay against the full pinned input, deduplicates source revisions and records materialization/acknowledgement or quarantine. [The host controller](../packages/agent-team/src/darkfactory/admission-controller.ts) checks source/lifecycle bindings and current authority, reconciles partial materialization and ingestion transitions, and requires inbox evidence for conflicts. The new compilation controller invokes these host SDK APIs through an injected host interface. Observe does not invoke them; live compiler-to-admission configuration remains open.

[Workflow materialization](../packages/agent-team/src/workflow-runtime.ts) creates the complete pinned task plan with immutable factory bindings and verifies concrete Team records on replay. The [five-stage template](../packages/agent-team/src/workflow-templates.ts) defines reproduction, implementation, machine verification, integration and release acceptance, ending with a `canary-accepted` artifact requirement. All factory tasks remain held: Team readiness/mutations/acceptance, workflow scans and coordinator execution enforce the hold; public APIs cannot inject or remove the binding. Observation and cancellation remain available. The admission barrier is always `closed`, including acknowledged records. No stage activation, controller-backed acceptance or release operation is available yet; ordinary workflows retain their existing behavior.

The host-only `DarkFactoryPolicyStore` records immutable policy revisions, operator gate receipts, independent pause reasons, revocation and admission decisions in `darkfactory-policy.jsonl`. It uses exclusive journal ownership, expected revisions, a canonical hash chain and sync-before-acknowledgment. Removing a host grant affects the next decision. Reopening after disablement requires reconciliation evidence. Decisions are control/admission audit receipts; they are not proof that an adapter performed an effect, and the runtime still needs an API for existing attempts pinned to older policy revisions. Default effect availability is empty.

[Offline migration](darkfactory-migration.md) supports policy, ingress, compilation, admission, provider-request and scanner journals through their native replay owners. It preserves exact event bytes in a separate layout, requires external reference validation on both copies, and publishes a commit only after fencing the original inode against older readers. Interrupted or corrupt layouts refuse writes; explicit isolated restore fixtures preserve the original backup.

Policy, ingress, compilation, admission, provider-request and scanner journals enforce configured record and aggregate byte limits on append and replay. Factory replay reads bounded chunks with fatal UTF-8 decoding, rejecting oversized and incomplete records without loading the entire journal. HTTP custody also enforces body/header, rate, queue, artifact and disk-watermark limits. Artifact storage checks aggregate capacity and existing content digests before reuse. The configured retention duration does not start automatic cleanup; retention jobs and full recovery targets remain open.

Secret-file resolution and pinned factory storage paths currently require Linux. [Descriptor-relative directory ownership](../packages/agent-team/src/darkfactory/paths.ts) and no-follow opens prevent symlink redirection of factory journals and artifacts. Secret resolution accepts only bounded, private files owned by the process user. Secret values remain host-only and never enter policy snapshots.

## Recovery runbook skeletons

These procedures define the evidence future control surfaces must record. They are not executable recovery commands for an already deployed Dark Factory service.

| Procedure | Required sequence and reopening evidence |
| --- | --- |
| Key rotation | Add the project-scoped verification key; verify a fixture; switch the signer; retain historical verification keys through evidence expiry. Revoke pending authority immediately and queue re-verification without deleting signatures. |
| Redis recovery | Stop paid admission; fence the old primary and hosts; restore durable Redis state; reconcile provider request IDs and outstanding reservations; withhold uncertain capacity. Record a successful contention probe and explicit reopening. |
| Quarantine review | Inspect source/spec/effect receipts; resolve the typed cause; record the authorized decision and a new immutable source/spec/policy revision. Preserve the failed attempt. |
| Forced disable | Persist safety pause; close ingress and paid/publication admission; fence workers; reconcile deployments. A separately preauthorized containment controller may finish withdrawal; unresolved effects remain visible. |
| Deployment outage | Freeze the environment; retain operation IDs; query bounded status recovery; use configured containment; escalate unknown exposure. Never create a new operation key to retry an uncertain effect. |
| Manual restoration | Identify exact live and prior immutable artifacts; verify service authority; record restoration intent, provider receipt and health evidence. Reconcile Git separately before reopening. |
| Disaster recovery | Restore journals, referenced artifacts and cursors into an isolated environment; reconcile every unresolved remote effect before writes. Validate backup/reference integrity and retain the original until a restore drill passes. Quarantine any unprovable storage gap. |

Migration must be offline under exclusive ownership: validate a backup, write a separate versioned store, replay and validate references, switch atomically, then prove restoration from the original. Unknown events, partial writes and broken hash chains block writes. Production qualification still requires the PRD's restore RTO/RPO and retention targets.

The host compiler-to-held-admission path is now durable. Wire it to registered coordinator configuration and an actually mediated compiler transport, with persisted policy decisions and economic authorization before any paid call. Preserve its stable attempt identity, bounded repair count and explicit uncertain-result handling. The [end-to-end synthetic issue fixture](../tests/darkfactory-source-workflow-restart.spec.ts) now covers authenticated custody, current provider reconciliation, full source/spec artifact checks, compilation and real Team materialization. It preserves one workflow/five held tasks across both named crash boundaries and verifies no new provider/compiler/task effects on a third replay. Full source-to-release qualification remains open.

Extend authoritative reconciliation to Sentry and APM and polling to the remaining supported sources. Full provider/artifact/attachment/trust fault coverage, mutable-pagination qualification and live adapter conformance remain open.

Stage activation requires a separate host controller and current authority; admission acknowledgement alone must never activate a task. The current compilation guard conservatively preserves earlier active work and quarantines a competing revision.

Build mode can expose intermediate verification receipts only once implemented; it cannot substitute them for terminal acceptance. This work does not enable paid providers, publication or deployment. Goals 1–5 remain open.
